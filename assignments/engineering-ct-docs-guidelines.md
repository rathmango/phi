# Engineering CT Docs Guidelines

CT(Computational Thinking) 4단계에 따라 일상 사물을 분해하고 추상화하여 디지털에서 다룰 수 있는 형태로 변환한다.

## 단계별 가이드

### 1. 분해

복잡한 시스템을 가장 작은 요소로 쪼갠 뒤, 이것들이 어떻게 결합하여 상위 목적을 달성하는지 하향식(Top-down) 트리 구조로 파악한다.

- 재질, 색상 같은 겉모습은 배제한다.
- 사물의 전체 목적, 즉 고수준 기능을 먼저 하나의 문장으로 정의한다.
- 그 목적을 달성하기 위해 작동하는 핵심 기능과 주요 프로세스 단계, 즉 중수준 단계를 나열한다.
- 중수준 단계에는 사용자의 조작(입력), 시스템 내부의 자율적 작동(처리), 현상 또는 결과(출력)를 모두 포함한다.
- 각 기능이 시스템의 어떤 상태나 변수를 변화시키는지 저수준 단위까지 쪼갠다.
- 분해는 각 사물별로 따로 진행한다.
- 가장 저수준에는 숫자로 나타낼 수 있는 표현이 오도록 분해한다.
- 분해 결과는 트리 구조 형태로 그린다.
- 탑다운과 바텀업 사고를 짧게 여러 번 반복하며 수정한다.
- 사물을 이용하는 시퀀스가 온전히 드러나는지 확인한다.

### 2. 패턴 인식

분해된 요소들 사이에서 반복되는 규칙과 결정적인 차이를 발견하고 비교 매트릭스 표에 나열한다. 표의 행과 열을 대조하며 모든 사물을 관통하는 핵심 작동 규칙과, 사물마다 제어 방식이 갈라지는 분기점을 문장으로 추출한다.

- 여러 사물의 분해 결과에서 보이는 공통 패턴과 차이 패턴을 하나의 비교표에 정리한다.
- 비교 분해 속성은 과제 목적에 맞게 바꿀 수 있다.
- 비교 분해 속성의 종류는 필요한 만큼 더하거나 뺄 수 있다.
- 분해에서 발견한 요소들이 비교표에 대부분 옮겨졌는지 확인한다.
- 분해에는 있으나 비교표에 없는 항목, 비교표에는 있으나 분해 결과에 빠진 항목이 없는지 확인한다.

### 3. 추상화

물리적 형태를 걷어내고, 시스템의 본질적인 특징을 보편적인 개념으로 바꾼다.

- `모래알의 양`, `태엽의 장력` 같은 물리적 실체를 그대로 쓰지 않는다.
- 이를 `보유한 에너지의 양`, `작동을 시작하는 물리적 신호`처럼 디지털 UI 시스템에서 활용할 수 있는 보편적인 속성(Property) 개념으로 바꾼다.
- 패턴 인식 결과로 한 문장의 추상화 모델을 만든다.
- 특정 사물이 아닌 새로운 장치나 프로세스를 설계할 수 있는 추상화 모델을 만든다.
- 이때의 추상화는 컴퓨터 사이언스 분야의 추상화를 뜻한다.
- 추상화의 정도는 목적 종속적이므로 의도적으로 조절한다.
- 본래 사물에 충실한 모델과 많이 일반화된 모델을 모두 상상한 뒤, 그 사이에서 적절한 추상화 강도를 고른다.
- 다른 사물을 대입해 추상화 강도를 점검한다.
- 본래 사물에만 맞으면 추상화가 적고, 너무 많은 대상이 들어맞으면 추상화가 과하다.

참고: https://en.wikipedia.org/wiki/Abstraction_(computer_science)

### 4. 플로우차트

추상화된 속성들이 조건(If/Else)에 따라 어떻게 상호작용하고 시스템의 상태를 변화시키는지 흐름을 정의한다.

- 먼저 인터페이스 개요를 한 문장으로 작성한다.
- UI가 가질 수 있는 명확한 상태를 나열한다. 예: 대기, 작동, 일시정지.
- 사용자의 조작이나 시간 경과 같은 조건이 발생했을 때 어떤 상태로 넘어가는지 시나리오 형태로 작성한다.
- 조건과 결과가 상태 변화로 이어지도록 정리한다.

### 5. 프로토타입

플로우차트에서 설계한 조건-결과 흐름을 실제 작동하는 디지털 결과물로 구현한다.

- Claude Code를 사용해 플로우차트의 시나리오를 코드로 옮긴다.
- 직접 코드를 작성하는 것이 아니라, 설계한 조건-결과 흐름을 자연어로 지시하여 구현한다.
- 핵심 흐름 하나가 먼저 작동하는 것을 확인한 뒤, 조건을 하나씩 추가하며 완성도를 높인다.
- 최종 결과물은 Vercel 등을 통해 실제로 조작할 수 있는 상태로 배포한다.
- 작동 과정을 영상으로 기록하여 제출한다.

## 작업 체크리스트

- [ ] 고수준 문장이 사물의 기능과 동작을 한 문장으로 표현하는가?
- [ ] 겉모습, 재질, 색상 설명을 핵심 분해 기준에서 제외했는가?
- [ ] 입력, 처리, 출력이 중수준 단계에 모두 포함되었는가?
- [ ] 저수준 항목이 숫자 또는 상태값으로 표현 가능한가?
- [ ] 사용 시퀀스가 분해 트리 안에서 끊기지 않고 이어지는가?
- [ ] 패턴 인식 표가 분해 결과의 주요 요소를 대부분 반영하는가?
- [ ] 공통 규칙과 차이 분기점이 문장으로 정리되었는가?
- [ ] 물리적 실체를 디지털 속성으로 바꾸었는가?
- [ ] 추상화 모델이 너무 좁거나 너무 넓지 않은가?
- [ ] 플로우차트에 명확한 UI 상태와 If/Else 조건이 있는가?
- [ ] 프로토타입에서 핵심 조건-결과 흐름이 실제로 작동하는가?

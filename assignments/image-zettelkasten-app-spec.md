# 이미지 제텔카스텐 앱 기획서 및 프로토타입 스펙

## 1. 제품 정의

Image Zettelkasten은 사용자가 오프라인 또는 온라인에서 발견한 디자인/조형 이미지를 수집하고, 직접 관찰 기록을 작성한 뒤, 카드 형태로 축적하고 다시 탐색하는 앱이다.

이 앱의 목적은 이미지를 단순 저장하는 것이 아니다. 사용자가 반복해서 이미지를 보고, 언어화하고, 태그와 메타데이터 기준으로 다시 묶어보면서 자신의 미적 기준을 선명하게 만드는 것이다.

앱이 대신하지 않는 것:

- 이미지를 발견하는 일
- 미감을 판단하는 일
- 관찰 문장을 대신 작성하는 일

앱이 자동화하는 것:

- 이미지 수집 이후의 반복 공정
- 이미지와 메타데이터 정리
- 관찰 항목 구조화
- 제목/주제 태그 후보 제안
- 카드 템플릿 배치
- 태그/메타데이터 기준 카드 묶음 생성

## 2. 핵심 컨셉

한 문장 컨셉:

> 이미지를 발견한 순간의 인상을 카드로 고정하고, 쌓인 카드를 태그와 메타데이터 기준으로 다시 펼쳐보는 미감 훈련 아카이브 앱.

핵심 구조:

```text
기본 화면 = 수집된 카드들을 보는 Library View
카드 추가 = Library View 안에서 진입하는 Add Card Mode
```

기본 경험은 카드 제작이 아니라 카드 탐색이다. 사용자는 앱을 열면 먼저 지금까지 쌓인 이미지 관찰 카드를 보고, 어떤 기준으로 묶어볼지 선택한다. 새 이미지를 기록하고 싶을 때만 카드 추가 모드로 들어간다.

## 3. 사용자 문제

사용자는 오프라인에서 눈에 띄는 조형을 촬영하거나, 온라인에서 마음에 드는 이미지를 저장한다. 하지만 그 이후의 정리 과정은 여러 도구에 흩어져 있다.

반복되는 문제:

- 이미지를 발견한 순간의 인상이 시간이 지나면 흐려진다.
- 사진/스크린샷을 Figma, 메모장, PPT 등 여러 도구로 옮겨야 한다.
- 촬영 날짜, 출처, 발견 장소 같은 정보를 매번 다시 확인해야 한다.
- 요소, 구성, 상태, 맥락, 효과를 같은 구조로 반복해서 기록해야 한다.
- 최종 카드를 만들기 위해 매번 템플릿에 이미지와 텍스트를 다시 배치해야 한다.
- 카드가 쌓인 뒤에도 어떤 기준으로 다시 묶어볼지 관리하기 어렵다.

이 앱은 위 과정을 하나의 공정으로 묶는다.

## 5. Library View 상세 기획

### 5.1 화면 목적

Library View는 사용자가 지금까지 수집한 이미지 관찰 카드를 다시 보고, 어떤 기준으로 묶어볼지 선택하는 기본 화면이다.

Library View에서 사용자는 다음을 수행한다.

- 전체 카드 보기
- 묶기 기준 선택
- 기준별 그룹 보기
- 카드 검색
- 카드 상세 열기
- 새 카드 추가

```text

├───────────────┬──────────────────────────────┬───────────────┤

```

## 6. 카드 묶음 규칙

카드 묶음은 폴더 방식이 아니다. 카드는 하나의 고정된 위치에 들어가지 않는다.

카드 묶음은 사용자가 선택한 기준 필드에 따라 그때그때 생성되는 보기 방식이다.

예를 들어 사용자가 `주제 태그` 기준을 선택하면, 시스템은 각 카드의 주제 태그 값별로 그룹을 만든다.

```text
거친 재질
- 카드 A
- 카드 C

문자 조형
- 카드 A
- 카드 F

여백
- 카드 B
- 카드 D
```

카드 A가 `거친 재질`, `문자 조형` 태그를 동시에 가지고 있다면 카드 A는 두 그룹에 모두 나타난다.

핵심 규칙:

- 하나의 카드가 여러 값을 가지면 여러 그룹에 중복 포함된다.
- 그룹은 저장된 폴더가 아니라 선택한 기준에 따라 계산되는 뷰다.
- 묶기 기준을 바꾸면 그룹 목록과 카드 그리드가 즉시 재구성된다.

## 7. Add Card Mode 상세 기획

### 7.1 진입 방식

Library View의 `카드 추가` 버튼을 누르면 Add Card Mode로 전환된다.

Add Card Mode는 라이브러리 기본 화면 위에 모든 기능을 펼쳐놓는 방식이 아니라, 한 장의 이미지를 카드로 완성하는 집중 흐름이다.

형태:

- 프로토타입에서는 전체 화면 전환 방식으로 구현한다.
- 상단에는 현재 단계 표시와 `라이브러리로 돌아가기` 버튼이 있다.
- 중앙에는 현재 단계의 핵심 작업만 보여준다.
- 하단에는 이전/다음 버튼이 있다.

### 7.2 Add Card 진입 방식

카드 추가 버튼을 누르면 별도의 업로드 화면으로 이동하지 않는다.

```text
Library View에서 카드 추가 클릭
→ 즉시 OS 기본 이미지/파일 선택 액션 열림
→ 이미지 선택 완료
→ draft 생성
→ Add Card Mode 시작
→ 첫 단계는 관찰 이미지화
```

사용자가 이미지 선택을 취소하면 Add Card Mode로 들어가지 않고 Library View를 유지한다.

### 7.3 Add Card 단계

```text
1. 관찰 이미지화
2. 메타데이터 확인
3. 관찰 기록 작성
4. 제목/주제 태그 확정
5. 카드 미리보기
6. 저장 후 라이브러리 복귀
```

## 8. Add Card Step 상세

### 카드 추가 액션. 이미지 수집

목적:

- 사용자가 새로 기록할 이미지를 앱에 넣는다.

화면 요소:

- 큰 `이미지 추가하기` 버튼
- OS 기본 이미지 선택 액션
- 안내 문장

문구 예시:

```text
오늘 눈에 걸린 이미지를 올리세요.
사진, 스크린샷, 저장 이미지를 사용할 수 있습니다.
```

입력:

- 이미지 파일

출력:

- 원본 이미지
- 파일명
- 수집 시간
- Add Card Mode 진입
- 관찰 이미지화 단계 시작

중요 원칙:

- 앱 안에서 `오프라인 촬영 / 온라인 저장` 같은 선택 UI를 만들지 않는다.
- 사용자가 이미지를 추가하기 전에 이미지의 성격을 먼저 분류하게 하지 않는다.
- `이미지 추가하기`를 누르면 운영체제의 기본 이미지/파일 선택 액션이 열려야 한다.
- 모바일에서는 OS가 제공하는 사진첩, 카메라, 파일 선택 흐름에 맡긴다.
- 데스크톱에서는 OS 기본 파일 선택 창에 맡긴다.
- 웹 프로토타입에서는 숨겨진 `<input type="file" accept="image/*" />`를 사용한다.
- 출처 URL, 수집 장소, 발견 맥락은 이후 메타데이터 단계에서 사용자가 보정한다.

### Step 1. 관찰 이미지화

목적:

- 원본 이미지에서 관찰하고 싶은 부분이 잘 보이도록 만든다.

화면 요소:

- 큰 이미지 미리보기
- 1:1 카드 비율 프레임
- 줌 조절
- 좌우 틸트 조절
- 리셋 버튼
- 현재 프레임 미리보기

프로토타입 구현 범위:

- 완전한 크롭 엔진은 구현하지 않는다.
- 고정된 1:1 프레임 안에 이미지가 들어가도록 줌과 좌우 틸트만 조정하는 간단한 이미지 편집기로 구현한다.
- 줌과 틸트는 Apple 사진 편집기처럼 미세 조정 가능해야 한다.
- 줌은 큰 프리셋 버튼 중심이 아니라 작은 step의 range control로 조정한다.
- 틸트는 좁은 각도 범위 안에서 0.1도 단위로 조정한다.
- `가로 위치`, `세로 위치` 같은 숫자/슬라이더 중심 UI를 노출하지 않는다.

입력:

- 원본 이미지

출력:

- 관찰용 이미지 상태
- 크롭 영역/위치 값

### Step 2. 메타데이터 확인

목적:

- 나중에 기억이 흐려지는 문제를 줄이기 위해 수집 정보를 카드에 붙인다.

기록하는 정보:

- 수집 날짜
- 수집 장소
- 파일명
- 출처 링크
- 발견 맥락

프로토타입 구현 범위:

- 실제 EXIF 정밀 파싱은 하지 않는다.
- 파일명, 현재 날짜, 사용자가 입력한 출처/장소/맥락을 메타데이터처럼 표시한다.

입력:

- 이미지 파일
- 사용자 입력 정보

출력:

- 카드 메타데이터

### Step 3. 관찰 기록 작성

목적:

- 사용자가 이미지를 보고 직접 관찰 문장을 작성한다.

화면 구조:

- 왼쪽: 관찰 이미지 고정
- 오른쪽: 다섯 개 질문 입력

질문:

```text
요소: 무엇이 보이는가?
구성: 어떻게 배치되어 있는가?
상태: 재질, 낡음, 빛, 손상은 어떤가?
맥락: 어디에서 어떤 상황으로 만났는가?
효과: 어떤 인상과 작용을 만드는가?
```

중요 원칙:

- 관찰 기록은 사용자가 직접 쓴다.
- 앱은 대신 작성하지 않는다.
- 앱은 질문 구조와 입력 흐름만 제공한다.

입력:

- 요소 기록
- 구성 기록
- 상태 기록
- 맥락 기록
- 효과 기록

출력:

- 관찰 문장 묶음

### Step 4. 제목/주제 태그 확정

목적:

- 관찰 기록을 바탕으로 카드의 제목과 주제 태그를 확정한다.

앱이 하는 일:

- 관찰 문장에서 반복 키워드를 찾는다.
- 제목 후보를 제안한다.
- 주제 태그 후보를 제안한다.
- 비슷한 기존 카드 후보를 보여준다.

사용자가 하는 일:

- 제안 제목을 그대로 쓴다.
- 제안 제목을 수정한다.
- 제안 태그 중 일부를 선택한다.
- 직접 태그를 추가한다.
- 제안을 무시하고 새로 쓴다.

입력:

- 관찰 문장
- 기존 카드 목록

출력:

- 확정 제목
- 확정 주제 태그

### Step 5. 카드 미리보기

목적:

- 저장 전에 최종 카드가 어떻게 보일지 확인한다.

카드 템플릿에 들어가는 정보:

- 관찰 이미지
- 제목
- 수집 시간
- 수집 공간
- 출처
- 요소 기록
- 구성 기록
- 상태 기록
- 맥락 기록
- 효과 기록
- 주제 태그

가능한 행동:

- 저장
- 이전 단계로 돌아가 수정

출력:

- 저장 가능한 이미지 제텔카스텐 카드

### Step 6. 저장 후 라이브러리 복귀

저장하면 새 카드가 cards 배열에 추가된다.

저장 후 동작:

- Add Card Mode 종료
- Library View로 복귀
- 새 카드가 선택 상태가 됨
- 현재 묶기 기준에 따라 그룹 목록과 카드 그리드가 갱신됨

## 최신 반영 사항: 크롭 에디터와 카드 템플릿

### 이미지 추가 액션

`카드 추가` 버튼을 누르면 앱 내부에서 오프라인/온라인을 다시 고르게 하지 않는다. 사용자의 OS가 제공하는 기본 이미지 선택 액션을 바로 연다.

구현 기준:

- `input type="file" accept="image/*"`를 숨겨두고, `카드 추가` 버튼이 해당 입력을 호출한다.
- 이미지를 선택하면 별도의 업로드 화면 없이 바로 `관찰 이미지화` 단계로 들어간다.
- 카메라 실행, 사진첩 선택, 파일 선택 등은 OS/브라우저의 기본 동작에 맡긴다.

### 관찰 이미지화: 실제 크롭 에디터

관찰 이미지화 단계는 숫자 슬라이더로 이미지를 흉내 내는 화면이 아니라, 실제 이미지 크롭 에디터여야 한다.

구현 기준:

- `react-easy-crop`을 사용한다.
- 크롭 프레임은 1:1 정사각형이다.
- 사용자는 이미지를 직접 드래그해서 프레임 안의 구도를 정한다.
- 크롭 배율은 미세 조정 가능해야 한다.
- 기울기 보정은 Apple 사진 편집기처럼 작은 단위로 조정 가능해야 한다.
- 다음 단계로 넘어갈 때 정사각형 크롭 결과를 생성하고, 이후 카드 템플릿에는 원본이 아니라 크롭된 이미지가 들어간다.

### 카드 템플릿 디자인

각 관찰 카드는 단순 썸네일 카드가 아니라, 인쇄 가능한 이미지 제텔카스텐 카드처럼 보여야 한다.

카드 한 벌의 기본 형태:

- 왼쪽: 이미지 카드
- 오른쪽: 기록 카드
- 배경은 차가운 연회색 앱 바탕
- 카드는 흰색 배경, 얇은 회색 외곽선, 약한 그림자를 가진다.
- 이미지 카드와 기록 카드는 같은 비율과 같은 모서리 값을 가진 한 쌍으로 배치된다.

이미지 카드 구성:

- 좌상단에 카드 번호를 둥근 외곽선 pill로 표시한다.
- 우상단에 대표 태그 1~2개를 검은 pill로 표시한다.
- 아래쪽에는 1:1 크롭 이미지가 크게 들어간다.
- 이미지는 카드 안에서 다시 임의로 늘어나지 않고, 크롭 결과 그대로 `object-cover`로 배치된다.

기록 카드 구성:

- 좌상단에 카드 번호를 둥근 외곽선 pill로 표시한다.
- 상단 중앙에는 제목을 크게 배치한다.
- 우상단에는 대표 태그 1~2개를 검은 pill로 표시한다.
- 첫 번째 수평선 아래에는 수집 날짜/시간/발견 맥락과 핵심 관찰 문장을 나란히 둔다.
- 두 번째 수평선 아래에는 태그 chip과 요소/구성/상태/맥락/효과를 합친 관찰 문장을 둔다.
- 하단에는 `-`와 `warm up` 같은 작은 footer를 둔다.

이 템플릿은 사용자가 예시로 제시한 이미지 카드/텍스트 카드 쌍을 기준으로 한다. 프로토타입에서도 라이브러리 우측 상세 패널과 카드 추가 마지막 미리보기 단계는 이 템플릿을 사용한다.

## 최신 반영 사항: 카드북 뷰와 모바일 OS식 크롭 편집기

### 카드 보기 방식

라이브러리는 카드 그리드에서 하나를 선택해 자세히 보는 구조가 아니다. 자세히 보기 패널도 필요하지 않다.

기본 보기 방식은 책처럼 한 장씩 넘기는 카드북 뷰다.

구현 기준:

- 항상 한 벌의 카드만 크게 보여준다.
- 왼쪽에는 이미지 카드가 온다.
- 오른쪽에는 기록 카드가 온다.
- 두 카드는 가로로 붙어 있는 하나의 spread처럼 보인다.
- 사용자는 `이전 카드`, `다음 카드`로 책장을 넘기듯 이동한다.
- 카드 추가 과정의 마지막 `미리보기` 단계는 제거한다. 완성된 카드의 형태 자체가 기본 라이브러리 뷰이기 때문이다.

### 모바일 OS식 이미지 크롭 편집기

관찰 이미지화 단계는 사이드 패널이 달린 데스크톱 설정 화면처럼 보이면 안 된다. 모바일 OS 기본 사진 편집기의 크롭 화면처럼 보여야 한다.

구현 기준:

- 화면 중심에는 큰 이미지 편집 영역이 있다.
- 이미지는 어두운 배경 위에 놓인다.
- 1:1 크롭 프레임이 이미지 위에 직접 표시된다.
- 사용자는 이미지 영역에서 드래그로 크롭 위치를 조정한다.
- 하단에는 도구 선택 영역이 있다.
- 하단에는 `1:1` 비율 선택이 명확히 보인다.
- 크롭 배율과 기울기 보정은 하단 슬라이더로 조작한다.
- 크롭 단계에서는 기존 앱 헤더와 일반 진행 footer를 숨긴다.
- 크롭 화면 안에서 `취소`와 `선택`을 처리한다.

## 최신 반영 사항: 크롭 배율 축소와 편집 배경 전환

크롭 배율은 기본값을 `1x`로 둔다. 사용자는 확대뿐 아니라 축소 방향으로도 조정할 수 있어야 한다.

구현 기준:

- 기본 크롭 배율은 `1x`다.
- 슬라이더는 `1x`보다 작은 값으로도 내려갈 수 있다.
- 실제 구현에서는 음수 스케일이 아니라 `0.25x`까지의 축소 배율로 처리한다.
- 음수 스케일은 이미지 반전이 되므로 크롭 배율의 의미와 맞지 않는다.

크롭 편집 배경은 검정으로 고정하지 않는다.

구현 기준:

- 기본 배경은 검정이다.
- 하단 도구 영역에서 `검정 배경`, `흰 배경`을 전환할 수 있다.
- 배경에 따라 크롭 프레임 선과 외부 마스크 대비도 함께 바뀐다.

## 최신 반영 사항: 갤러리형 카드 목록

책처럼 한 장씩 넘기는 방식은 카드 수가 늘어났을 때 탐색 밀도가 낮다. 기본 라이브러리 뷰는 다시 갤러리형 스크롤 목록으로 조정한다.

구현 기준:

- 카드 형태는 유지한다.
- 하나의 기록은 `왼쪽 이미지 카드 + 오른쪽 기록 카드`가 붙은 한 벌로 보인다.
- 자세히 보기 패널은 만들지 않는다.
- 카드를 선택해서 별도 상세 화면으로 여는 흐름도 만들지 않는다.
- 필터/검색 결과에 해당하는 카드들이 전부 같은 형태로 아래로 쌓인다.
- 데스크톱에서는 한 행에 카드 한 벌이 2개씩 배치된다.
- 모바일 또는 좁은 화면에서는 한 행에 카드 한 벌이 1개씩 배치된다.
- 사용자는 갤러리처럼 아래로 스크롤하며 카드를 본다.

## 최신 반영 사항: 크롭 프레임 고정

기울기 보정은 이미지의 각도만 바꾸는 기능이다. 프레임은 이미지 회전에 따라 커지거나 줄어들면 안 된다.

구현 기준:

- 크롭 비율은 무조건 `1:1`이다.
- `4:3`, `16:9` 등 다른 비율 선택 UI는 제거한다.
- 크롭 배경은 무조건 흰색으로 고정한다.
- 검정/흰 배경 선택 UI는 제거한다.
- 기울기 보정을 해도 1:1 크롭 프레임의 크기는 고정된다.
- 구현에서는 `react-easy-crop`의 `cropSize`를 명시해 회전 시 crop area가 자동으로 재계산되어 흔들리는 문제를 막는다.

## 최신 반영 사항: 크롭 컨트롤 간소화와 휠 줌 금지

크롭 단계의 하단 UI는 세로 공간을 크게 차지하면 안 된다.

구현 기준:

- `1:1 고정` 안내 박스는 제거한다.
- 비율 선택 UI는 존재하지 않는다.
- 크롭 배율과 기울기 보정은 각각 한 줄 안에서 처리한다.
- 각 줄은 `라벨 / 슬라이더 / 현재 값` 구조로 만든다.
- 큰 리셋 영역과 설명 문구는 제거한다.
- 리셋은 이미지 편집 영역 위의 작은 아이콘 버튼으로 둔다.

스크롤 휠은 이미지 확대/축소에 사용하지 않는다.

구현 기준:

- 화면을 스크롤하다가 이미지가 커지거나 작아지면 안 된다.
- 크롭 배율은 하단 슬라이더로만 조정한다.
- `react-easy-crop`의 `zoomWithScroll`은 비활성화한다.

## 최신 반영 사항: 카드 비율 정의

카드의 단위는 이미지 카드와 기록 카드를 합친 spread가 아니다. 각각의 낱장 카드가 카드 단위다.

구현 기준:

- 이미지 카드 1장의 비율은 `5:6`이다.
- 기록 카드 1장의 비율도 `5:6`이다.
- 한 관찰 기록은 이미지 카드와 기록 카드가 좌우로 붙은 한 벌로 표시된다.
- 따라서 한 벌 전체의 비율은 `10:6`이다.
- 갤러리에서 한 아이템은 이 `10:6` spread다.

## 최신 반영 사항: 모바일 크롭 화면 밀도

모바일 크롭 화면에서는 상단/하단 여백이 크게 남으면 안 된다.

구현 기준:

- 크롭 단계에서는 main padding을 최소화한다.
- 모바일에서는 크롭 화면이 화면 폭에 붙어도 된다.
- 헤더 높이는 낮게 유지한다.
- 편집 영역은 `100svh` 기준으로 헤더와 하단 컨트롤을 뺀 나머지 높이를 사용한다.
- 불필요한 상단/하단 그라디언트 마스크는 제거한다.
- 하단 컨트롤은 컴팩트하게 유지한다.

## 최신 반영 사항: 카드 모서리, 번호, 이미지 카드 헤더

카드 자체에는 radius를 주지 않는다. 카드 형태는 직각의 인쇄물처럼 보이게 한다.

구현 기준:

- 이미지 카드와 기록 카드의 외곽 모서리는 둥글게 처리하지 않는다.
- 한 벌 spread의 외곽 모서리도 둥글게 처리하지 않는다.
- `warm up`처럼 의미 없는 장식 텍스트는 카드에서 제거한다.
- 카드 번호는 등록된 순서대로 `1`, `2`, `3`, `4`...가 들어간다.
- 이미지 카드 상단에는 카드 번호와 제목만 들어간다.
- 이미지 카드 상단에는 태그를 넣지 않는다.

## 최신 반영 사항: 오른쪽 기록 카드는 줄글 관찰문

오른쪽 기록 카드는 `요소 / 구성 / 상태 / 맥락 / 효과`를 표처럼 나누어 보여주지 않는다.

구현 기준:

- 왼쪽 이미지 카드는 식별 정보를 담당한다.
- 왼쪽 이미지 카드 상단에는 등록 순서 번호, 제목, 수집 날짜/시간만 둔다.
- 오른쪽 기록 카드에는 번호, 제목, 시간, 태그를 반복하지 않는다.
- 오른쪽 기록 카드는 하나의 줄글 관찰문만 담는다.
- 관찰문에는 요소, 구성, 상태, 맥락, 효과가 필요하면 자연스럽게 섞여 들어간다.
- 입력 단계에서도 다섯 항목으로 나누지 않고 하나의 관찰문 textarea만 제공한다.

## 최신 반영 사항: 카드 정보 배치 재정리

왼쪽 이미지 카드는 카드의 식별 정보를 담당한다. 오른쪽 기록 카드는 기록 본문과 태그를 담당한다.

구현 기준:

- 왼쪽 카드 상단에는 번호, 제목, 수집 날짜/시간/장소가 들어간다.
- 수집 날짜, 시간, 장소는 한 줄에서 `·`로 구분한다.
- 번호 pill은 불필요하게 큰 padding을 주지 않는다.
- 오른쪽 카드에는 번호, 제목, 날짜, 시간이 반복되지 않는다.
- 오른쪽 카드 본문은 `관찰`과 `인사이트` 두 영역으로 나눈다.
- `관찰`은 보이는 것과 맥락을 하나의 줄글로 쓴다.
- `인사이트`는 왜 눈에 걸렸는지, 어떤 조형적 효과를 만드는지 줄글로 쓴다.
- 오른쪽 카드 하단에는 주제 태그를 배치한다.
- 태그는 상단에 중복 배치하지 않는다.

## 최신 반영 사항: 오른쪽 카드 타이포와 선 정리

오른쪽 기록 카드의 가로선은 구조적 의미가 없으면 사용하지 않는다.

구현 기준:

- 오른쪽 카드에서 장식적인 가로선은 제거한다.
- 왼쪽 카드의 정보 영역 높이에 맞춰 오른쪽 본문 시작 위치를 정렬한다.
- `관찰`, `인사이트`는 흐린 캡션이 아니라 본문 위의 헤딩이다.
- `관찰`, `인사이트` 헤딩은 본문과 같은 색상, 같은 크기를 사용한다.
- 헤딩은 본문보다 weight만 조금 더 준다.
- 의도적으로 자간을 넓히는 효과는 사용하지 않는다.

## 최신 반영 사항: 관찰/인사이트 단계 분리와 태그 입력

관찰과 인사이트는 한 화면에서 동시에 쓰지 않는다.

구현 기준:

- 관찰 작성 단계에는 관찰 textarea 하나만 둔다.
- 다음 단계로 넘어가면 인사이트 작성 단계가 나온다.
- 인사이트 작성 단계에는 인사이트 textarea 하나만 둔다.
- 이후 제목/태그 확정 단계로 넘어간다.

태그는 다중 입력을 기본으로 한다.

구현 기준:

- 시스템은 여러 개의 주제 태그를 제안할 수 있다.
- 사용자는 제안 태그를 그대로 쓰거나 직접 수정할 수 있다.
- 태그 입력창에서 쉼표를 입력하면 새로운 태그로 분리된다.
- 분리된 태그는 chip 형태로 즉시 확인할 수 있다.
- 최종 카드 오른쪽 하단에는 확정된 주제 태그들이 표시된다.

## 최신 반영 사항: 카드 액션 메뉴와 태그 위치

각 카드에는 우측 상단 액션 메뉴를 둔다.

구현 기준:

- 카드 우측 상단에 `…` 메뉴 버튼을 둔다.
- 메뉴에는 `수정`, `삭제`가 있다.
- `수정`을 누르면 해당 카드 데이터를 편집 흐름으로 불러온다.
- 편집 저장 시 새 카드가 아니라 기존 카드를 업데이트한다.
- `삭제`를 누르면 바로 삭제하지 않는다.
- `정말 삭제하시겠습니까?` 확인 모달을 띄운다.
- 모달에는 `확인`, `취소` 버튼이 있다.
- 확인을 누르면 카드가 삭제된다.

오른쪽 기록 카드에서 태그는 하단이 아니라 본문 위로 올린다.

구현 기준:

- 오른쪽 카드 본문 시작점은 왼쪽 이미지 시작점과 맞춘다.
- 태그는 오른쪽 카드 상단, 본문보다 위에 배치한다.
- 태그를 위로 올려 본문 길이가 늘어나도 하단이 덜 깨지게 한다.

## 최신 반영 사항: 이미지 EXIF 메타데이터 자동 읽기

이미지를 추가할 때 수집 날짜/시간을 파일 추가 시점으로 대충 채우면 안 된다. 먼저 이미지 파일의 메타데이터를 읽는다.

구현 기준:

- 이미지 선택 직후 `exifr`로 EXIF 메타데이터를 읽는다.
- `DateTimeOriginal`, `CreateDate`, `ModifyDate` 순서로 촬영/생성 시간을 찾는다.
- 촬영 시간이 있으면 `수집 날짜`, `수집 시간`에 자동 반영한다.
- GPS 정보가 있으면 `수집 공간`에 위도/경도 좌표를 자동 반영한다.
- EXIF가 없는 이미지, 스크린샷, 웹에서 저장되며 메타데이터가 제거된 이미지는 현재 시각으로 fallback한다.
- 자동으로 채워진 값은 메타데이터 단계에서 사용자가 수정할 수 있다.
